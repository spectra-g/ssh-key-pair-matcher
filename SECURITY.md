# Security policy

## Supported versions

There is no supported production release yet. Once releases begin, the latest
production version will receive security fixes.

## Reporting a vulnerability

Do not include private keys, passphrases, or other secrets in a report. Reproduce
issues only with disposable test material.

After the public GitHub repository is configured, use its private
**Report a vulnerability** form. Do not open a public issue for an unpatched
vulnerability.

Until that private channel exists, contact the maintainer through the same
private channel by which you received this source. Include:

- the affected commit or version;
- a concise impact description;
- minimal reproduction steps using non-sensitive fixtures; and
- any suggested mitigation.

Please allow a reasonable period for acknowledgement, investigation, and a
coordinated fix before public disclosure.
